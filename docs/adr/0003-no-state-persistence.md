# 不持久化任何状态：应用重启即开始一个新的工作时段

应用不保存任何进度。每次启动都从零开始一个 60 分钟的工作时段，退出前的进度全部丢弃。

这是刻意的产品行为，不是遗漏——"打开就开始计时"正是这个工具的用途，重启不该把用户丢进一个中途开始的时段。因此项目里不存在**计时状态**的持久化代码，将来也不应被当成待补的缺陷顺手"修好"。如果确实需要跨重启保留进度，那是一次产品行为变更，应当先明确提出并重写这个决策。

## 例外一：引导标记

引导标记（`~/Library/Application Support/<identifier>/.onboarded`）记的是"引导与通知权限申请已经做过"。

它记的是**一次性引导**，不是任何计时进度——工作时段、休息时段、暂停、待确认提醒，一个都不落盘。重启后照旧从零开始 60 分钟，与本决策完全一致。

之所以要留这个口子：macOS 的通知权限只弹一次，用户当时没留意就永久变成"拒绝"，之后所有通知静默失败。引导必须每次启动都判断"做过了没有"，而"做过了没有"总得有个地方记着。

## 例外二：单实例的 socket（它什么也不记）

单实例插件（`tauri-plugin-single-instance`）在 macOS 上靠一个 unix socket 认亲：`/tmp/<identifier 把 . 和 - 换成 _>_si.sock`。第二个实例起来时连上它、把参数交给第一个，然后自己退出。

这个 socket **不是状态**：它不记计时进度，也不记任何跨重启的东西——退出时插件自己删掉它，`/tmp` 本身也会被系统清空。它甚至不在应用的数据目录里。

## 例外三：单实例的名分锁（它什么也不记）

`/tmp/<identifier 把 . 和 - 换成 _>_si.lock`，零字节。进程用 `File::try_lock` 抢它：抢到的是那个唯一的实例，抢不到的立刻退出。

这个锁**不是状态**：它不记任何东西——锁看的是"哪个进程持着这个文件的描述符"，不是"文件里有什么"。文件里是空的。进程退出（哪怕是被 SIGKILL 掉的）锁自动松开，所以它不会留下"锁住不放"的死锁；文件本身留着也没关系，`/tmp` 会把它清掉。

之所以要它：插件在 macOS 上的认亲是"先连后绑"——连不上 socket 才去绑。这两步之间有个缝，两个进程能同时挤进去，绑输的那个插件会照样把应用跑起来，于是菜单栏上多一个托盘图标、多一套提醒。排他锁没有这个缝。

之所以把它写进这份决策：早先那句"磁盘上只允许存在一个文件"现在已经不准确了，落盘的东西有三个了。写下来是为了让那句话重新变成准确的，而不是把这条线悄悄挪了位置——多出来的那两个是单实例机制带来的，绕不开，也不该假装它们不存在。

这三个例外都**不能扩大**：新增任何落盘的东西之前，先回来改这份决策。
