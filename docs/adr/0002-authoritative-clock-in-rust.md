# 状态机与权威时钟放在 Rust 侧，不放在前端

这是 macOS 菜单栏常驻应用，面板默认隐藏，绝大多数时间只有托盘图标可见。如果心跳（每秒 tick）跑在前端的 `setInterval` 里，WKWebView 在不可见窗口中会被降频节流——剩余时间会卡住，到点提醒会迟到。

因此 `deadlineMs` 与状态机放在 Rust：一个内部线程持有权威时钟，自己校验到期、自己更新托盘标题、自己发通知和音效；快照在**状态或显示秒数变化时**推给前端（倒计时中即每秒一帧），前端拿 `deadlineMs` 本地插值渲染倒计时。节流即使发生也只影响显示，不影响真值。

> **为什么不是「仅状态变化时 emit」**：前端用自己的 `Date.now()` 算剩余，Rust 用 `SystemTime::now()`，两个时钟可能差几秒。每秒推一帧相当于持续对时——前端每帧都能把显示拉回 Rust 的真值。改成仅状态变化就没有任何纠偏机制了，那点偏差会一直留在面板上。代价只是每秒一条 IPC 消息。

代价：核心逻辑用 Rust 写（单元测试相应地用 `cargo test` 而非 Vitest），且给项目引入了 Rust 工具链这一道门槛。
