# 08 — 单实例

Status: resolved

## 目标

保证同一时刻只有一个计时进程在跑。重复启动 `.app` 时不产生第二个实例。

## 验收

- [x] 引入 `tauri-plugin-single-instance`
- [x] 第二次启动时：已有实例被激活（显示面板），新进程立即退出
- [x] 反复双击 `.app` 5 次，菜单栏只有**一个**托盘图标，只有一套提醒
- [x] 在 `lib.rs` 中把单实例插件注册在**第一个**插件位置（早于托盘与时钟线程初始化）
- [x] capability 里补上单实例插件所需权限 —— **一条都不用加**，见 Comments

## 背景

- 没有单实例时，重复双击会跑两个独立的 60 分钟计时器，两边都提醒、托盘出现两个图标
- 依赖 01 的骨架与 04 的托盘实现

## Comments

### 2026-10-24 — 落地了：一个插件 + 一道自己发的名分

**新增依赖**：`tauri-plugin-single-instance` 2.5。

**新增文件**：

- `src-tauri/src/single_instance.rs` —— 名分锁、通知、面板回调；
- `src-tauri/tests/single_instance.rs` —— 两个**进程级**用例（真拉起应用二进制）。

**`lib.rs` 的接线**：`run()` 的最前面判名分，抢不到就退出；插件注册在 builder 的第一个插件位置。

单实例这件事拆成了两半：

- **名分**（谁是那个唯一的实例）我们自己发；
- **认亲**（后来的那个怎么告诉先到的那个"我来了"）交给插件。

### 关键的一条：插件在 macOS 上的认亲有个缝

插件在 macOS 上靠一个 unix socket 认亲，顺序是**先连后绑**：连不上 socket（`NotFound` / `ConnectionRefused`）就认定"没有别人在"，把 socket 清掉，然后自己绑上socket 听着。

这两步之间有个缝，两个进程能同时挤进去。挤进去的结局是：绑赢的那个成了单例，绑定失败的那个插件会打一条错误日志，然后**照样把这个应用跑起来**——托盘图标、时钟线程、提醒，全套再来一份。菜单栏上于是有了两个托盘图标，两边到点了各响一次。

这不是推演，是量出来的。拿两个进程间隔不同的时间各起一次，数最后活下来几个：

| 两次启动的间隔 | 活下来的进程数 |
|---|---|
| 2ms / 5ms / 10ms / 20ms | **2**（漏了） |
| 50ms / 100ms / 300ms / 1s | 1（正常） |

那个缝有二十来毫秒宽。人手双击 `.app` 很难落进去（两次启动至少隔一百多毫秒），但脚本、自动化、`open -n` 都能落进去——而这票要的正是"同一时刻只有一个计时进程在跑"，所以这个缝得堵。

**堵法**：名分不交给插件，我们自己发。`File::try_lock` 是内核级的排他锁，没有"两个进程都拿到"的可能：

- 抢到锁的才是那个唯一的实例；
- 没抢到的立刻退出（而且是在 Tauri 起来**之前**退出——托盘、时钟线程、webview 都还没开始建）；
- 锁跟着 fd 走，进程崩了也自动松开，不会留下"锁住不放"的死锁。

`File::try_lock` 是 std 的 API（1.89 稳定），不用加依赖。锁文件是 `/tmp/<identifier>_si.lock`，零字节，跟 socket 做邻居。

**名字的来历**："名分"是这套代码里对这件事的说法——`claim()` 抢的是名分，`HELD_LOCK` 存的是名分。

### 名分不抢到，怎么让先到的那个把面板显示出来

后来的进程抢不到名分就退出，但它得先告诉先到的那个"有人来了"。走插件的 socket：连上去就走，什么都不写——插件的监听器读到空消息也会照样调回调（它把空串当成"没有参数"）。

对方可能还在启动、socket 还没绑上，所以重试一小会儿（上限 1 秒，每 10ms 一次）。正常情况下对方早就跑起来了，第一下就连上了。

### 面板可能还没建好：等它一会儿

面板窗口是 Tauri 在事件循环起来（`Ready`）之后才建的，而 socket 在 `build()` 末尾就绑上了——中间差着起 webview 的那几百毫秒。这时候来的第二个实例，"显示面板"会落空：面板还不存在。

这不是假想：`build()` 末尾绑好 socket → 第二个实例连上来 → 回调触发 → 面板还没建好 → 什么都没发生。用户看着自己点的 `.app` 跟没点一样。

所以 `on_second_instance` 先等面板建好（最多 1 秒）再显示。这个等待跑在插件的监听线程上，不是主线程，主线程该干嘛干嘛。

### capability 里一条权限都不用加

票里写的是"capability 里补上单实例插件所需权限"。实测**一条都不需要**。

插件没有 `permissions/` 目录，`build = false`，没有 `invoke_handler`——它整件事都在 Rust 侧发生，前端根本没有任何命令可以调。硬写一条 `single-instance:default` 进去，构建直接失败：

```
Permission single-instance:default not found, expected one of core:default, ...
```

所以 `capabilities/default.json` 的权限列表没动，只在描述里把这笔账记下来了，免得下一个人以为漏了。

### 验证分三层

1. **真机（这台机器，屏幕没锁也不影响）**：
   - 先起一个实例，再前台连着双击 5 次 → 每次**退出码 0、耗时 10~42ms**；第一个实例一直活着；`pgrep` 数下来**只有 1 个进程**；面板从"藏着"变成 `onscreen=true`（320x380 @ 560,252）——被后来的实例叫出来了。
   - 两个进程几乎同时起 → 活下来的正好 1 个，另一个退出；面板同样被叫出来。
   - 装闸门之前，同样两个实验：第二个实验**两个都活着**（两个托盘图标、两套提醒）。
2. **进程级用例**（`src-tauri/tests/single_instance.rs`，2 个）：
   - `a_second_launch_exits_at_once_and_the_first_one_keeps_running`：起 1 个真进程当单例，再起 4 个后来的（= 反复双击 5 次），每个都该在 15 秒内干净退出（0），第一个还活着，而且**它的 stderr 里该有"第二个实例"**——说明消息送到了、它有反应。
   - `two_instances_started_at_once_leave_only_one_running`：两个进程几乎同时起，**活着的只能有一个**。
   - 两条都验过"有牙齿"：把闸门关掉（`if false && ...`），第二条立刻红——`a 活着=true，b 活着=true`。
3. **单元用例**（`src-tauri/src/single_instance.rs`，4 个）：socket 路径、锁文件路径（都是插件/自己定的规矩）、以及"两个 `File` 抢同一把锁只有一个能拿到"。

真机那层能看见"面板真的出现了"，用例那层看不见窗口服务器（`CGWindowList` 那套得单独写工具），所以分工是：用例盯"进程与消息"，真机盯"面板在不在屏幕上"。

### 双轴评审之后改了什么

`/code-review` 跑了两条轴（standards / spec），都挑出了东西：

- **注释跟事实相反**（最要紧的一处，两处）：原来写的是"插件排在第一位，第二个进程就会在多出托盘图标、多起一个时钟线程之前退出；顺序反了的话，菜单栏上会闪出一个图标"。前半句对，后半句**错**——所有插件的 `setup` 钩子都跑在 `Builder::build()` 末尾，应用自己的 `setup`（建托盘、起时钟）要到 `Ready` 才跑，所以第二个进程一定早于托盘和时钟退出，跟插件之间排第几个**无关**。已改成如实的样子：插件排第一位的理由是插件 README 和票都这么要求（认亲的通道该在别的插件动手之前准备好），而不是"否则会闪出托盘图标"。
- **"用例会等错信号"**（真 bug）：原用例拿 `socket.exists()` 当"单例已就位"的信号。上次跑崩了残留的 socket 文件还在（它没人听），于是用例在第一个进程还没当上单例时就开始拉第二个 → 第二个抢下 socket → 失败信息还写着"第一个实例没当上单例"，指向错了方向。已改成**连一下**才知道有没有人真在听（`someone_is_listening`）。验过：把旧信号换回去，配一个残留 socket，用例立刻红（"第 1 个后来的实例没有退出"）；换新的，绿。
- **纯逻辑那层是空的**：`SecondInstanceReaction` 只有一个变体，`reaction_for_second_instance()` 永远返回它，那条用例是同义反复（`assert_eq!(x, x)`）。已删。纯逻辑那层现在放的是真有内容的东西：socket 路径、锁文件路径。
- **socket 路径的规矩写了两遍**：模块文档里一遍、用例里抄一遍。已收成一处——规矩在 `single_instance::socket_path`，用例调它。
- **票没更新**（本文件）、**`spec.md` §2 那行过期**（ADR-0003 已经有三个例外了，那行还写着"唯一例外是引导标记"）：都已改。
- **ADR-0003**：多了一个"名分锁"这个例外（第三个），已补一节。
- **Cargo.lock 被顺手升了格式**（v3 → v4）：那是 cargo 自己干的活，跟这票无关。已把它按回 v3，现在 diff 里只剩新增的依赖。

评审还提了两条，**没有**改，理由记在这里：

- **"capability 少了一条权限"**——不是少，是一条都不需要（上面那条已经查到底：插件没有 `permissions/` 目录、没有 `invoke_handler`）。票里的措辞跟事实对不上，改的是票。
- **"插件不支持移动端"**——确实不支持（它只有 macOS / Linux / Windows 三份实现，iOS/Android 上连编译都过不了）。本项目只做 macOS（spec §2「跨平台：决策：仅 macOS」），所以不影响。真要跨平台，这行得加 `#[cfg(desktop)]`。

### 顺带

- 插件的 `semver` 特性**没有**打开：打开的话 socket 路径会带上版本号，不同版本就不打架了。我们没开——开发版和打包版共用同一个 socket，打包版在跑的时候 `tauri dev` 起的实例会立刻让位。同一台机器上本来就只该有一个计时器在跑。
- 插件的 `setup` 钩子现在只干"认亲"这一件事（绑 socket、听消息、调回调）。它原来那条"连上了就 `exit(0)`"的路，后来的进程走不到了——它们在 Tauri 起来之前就退了。
- `rust-version` 从 1.77 抬到了 1.90：单实例插件自己声明的最低版本就是 1.90（依赖的下限比自己高，本 crate 只能跟着抬）。`File::try_lock` 要 1.89，也在这个下限之内。
